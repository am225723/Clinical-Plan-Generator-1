Enhance the existing Clinical Documentation App. The **AI treatment plan generator is already implemented**. Do **not** rebuild it. Implement the remaining features using:
 
 
- **Next.js Pages Router** (not App Router)
 
- **Supabase Auth + Postgres + Storage**
 
- **Supabase Edge Functions (Deno)** for privileged operations and PDF generation
 
- Deploy on **Vercel**
 

 
### Primary Goal
 
Finish the product workflow: role-based auth, admin user management, provider settings (editable AI prompt, PDF template styling), logo upload, validation UI, and PDF generation.

# 2) Supabase Auth + Roles
 
Use Supabase Auth for login.
 
Create `profiles` table:
 
 
- `id uuid primary key references auth.users(id)`
 
- `role text check (role in ('admin','doctor')) not null`
 
- `full_name text`
 
- `disabled boolean default false`
 
- `created_at timestamp default now()`
 

 
Implement role lookup:
 
 
- On login/session load, fetch `profiles.role` for the current user.
 
- Use role to gate UI and pages.
 

 
RLS policies:
 
 
- Users can read/update their own profile (limited fields).
 
- Admin can read all profiles.
 
- Doctors cannot read other doctors’ profiles.

# 4) Supabase Edge Functions (Must Use)
 
All privileged server actions must go through Edge Functions and be invoked from the Next.js frontend.
 
Create these Edge Functions:
 
## A) `admin-create-user`
 
Admin creates a new Doctor user.
 
 
- Auth required
 
- Verify caller is admin by reading `profiles.role`
 
- Use service role inside the Edge Function to create user
 
- Insert/update `profiles`
 

 
Inputs: `{ email, password? (optional), full_name }` Output: `{ user_id, email, full_name, role:'doctor' }`
 
## B) `admin-update-user`
 
Admin edits user or disables/enables. Inputs: `{ user_id, full_name?, disabled? }` Admin-only.
 
## C) `settings-get` and `settings-set`
 
Editable AI prompt stored in `app_settings` table:
 
 
-  
`id uuid pk`
 
 
-  
`treatment_plan_prompt text`
 
 
-  
`updated_at timestamp`
 
 
-  
`settings-get`: admin + doctor can read
 
 
-  
`settings-set`: admin-only (default)
 
 

 
## D) `logo-upload-sign`
 
Return a signed upload URL (or signed policy) for uploading a logo to Supabase Storage bucket `logos`.
 
 
- Store path like `doctor/{doctor_id}/logo-{timestamp}.png`
 
- Update `doctor_document_settings.logo_url`
 

 
## E) `pdf-generate`
 
Generate the final PDF using doctor settings. Inputs:
 
 
- patient + encounter info
 
- treatment plan content (already generated by AI)
 
- consent text
 
- signature block data Rules:
 
- **Informed Consent must appear directly above signatures**
 
- Do **not** print “Missing Required Data” or similar warnings in PDF
 
- If required fields missing, return `{ missing_fields: [...] }` and no PDF
 
- Return PDF bytes or a signed download URL
 

 
Edge compatibility:
 
 
- Use a Deno-compatible PDF solution.
 
- Keep within Edge runtime limits.
